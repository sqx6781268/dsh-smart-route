# 多链路由 · dsh-smart-route

让 DeepSeek Harness 在模型暂时不可用时，按你安排好的顺序继续寻找可用成员。你可以分别准备“质量优先”“快速响应”“备用通道”等多条链，每次对话直接选择适合当前任务的一条。

## 它能帮你解决什么

你可能同时有几个模型或服务渠道：一个擅长复杂任务，一个响应更快，还有一个适合备用。逐个手动切换容易打断工作；某个成员配额耗尽时，下一次请求还重复碰壁，也会浪费等待时间。

多链路由把这些选择整理成可以重复使用的方案：

- **复杂任务优先质量**：先用最合适的模型，暂时失败再尝试备用成员。
- **日常问答优先速度**：把响应更快的成员放在另一条链前面，不必为每次任务重新排顺序。
- **同类模型准备多个渠道**：一个渠道认证失败或配额用完时，自动尝试后面的成员。
- **明确知道实际用了谁**：会话顶部显示本会话最近实际开始作答的成员，设置页也可查看最近降级与冷却情况。

插件不会提供模型、账号或免费额度，也不会替你登录服务商。你需要先在 DSH 中配置好至少一个可以正常使用的模型；备用链通常需要两个以上成员。

## 特点与使用边界

**多条独立方案，手动决定用哪条。** 选质量链就按质量链执行，选快速链就按快速链执行。插件不会根据角色或问题内容擅自改选另一条链。

**回答开始前切换，避免拼接两家的半截答案。** 失败成员还没开始交付有效回答时，会放弃它并尝试后续成员；仅有思考内容也可以继续切换。为避免失败成员的思考混入对话，开始正式回答前会暂存思考内容，期间界面可能保持等待；成功开始作答后再一起显示，失败成员的暂存内容会丢弃。一旦已经开始交付回答或工具调用，再发生故障会把错误交给你，不会偷偷换人续写。

**确定性失败先冷却。** 默认对认证、凭据和配额类错误冷却五分钟；普通超时、限流和服务器暂时错误不进入默认冷却。冷却按成员跨链共享；如果整条链都在冷却，仍会尝试全部成员，避免只因冷却就完全无法请求。

**编辑后用于下一次请求。** 保存链配置后无需为换成员重启 DSH。正在进行的请求继续使用它开始时的方案。

**图片：只交给声明了「文本 + 图片」的成员。** 一条链里若有成员**在本次请求时**同时声明支持文本与图片，这条链就对宿主宣称支持图片；含图片的请求只会交给这些成员，其它成员在这次请求里被跳过（状态页的「图片筛选」列会记下原因）。没有任何这类成员时，链**明确拒绝**含图片的请求，不会把图片转成文字、也不会改用纯文本成员顶上。纯文本请求完全不受影响：候选顺序、降级与冷却与以前一致。

**图片能力与代价。** 混合链（视觉成员 + 纯文本成员）必须宣称支持图片才能让视觉成员收到历史图；代价是有图请求里纯文本成员会被筛掉，在它们身上配置的降级顺序对这类请求不生效。当前离线版本只验证到"识别与筛选正确"这一层，**未做真机视觉对照**，也不承诺任何服务商对图片的实际接受度。

**两个入口，同一份配置。** 可从设置中的多链路由标签进入，也可从插件详情进入。未保存的草稿分别保留；另一处配置更新时，过期草稿不能直接覆盖新配置，需要先重新加载或整理草稿。

备用服务仍可能计费；插件不承诺免费、不承诺每次请求都成功，也不替代服务商的用量限制。模型能力不同的成员混排时，应按链中较弱的能力安排任务。

图片相关的完整契约、边界与测试矩阵见 [图片路由契约](docs/图片路由契约冻结.md)；其中「插件看不到纯文本链的历史图」等宿主侧限制在 [配置说明](docs/配置说明.md#图片路由) 里也有使用口径。

## 支持环境

- DSH **0.2.1-rc.2**：首发支持和已验证的宿主版本。其他版本不默认视为兼容。
- Node.js **24 或更新版本**，桌面版优先使用 DSH 自带环境。
- 本机桌面和本机 Web 使用。配置页面不支持直接暴露到公网；远程连接或代理访问不在首发支持范围内。

## 安装

### 普通用户：安装发行包

1. 打开 [最新发行版](https://github.com/sqx6781268/dsh-smart-route/releases/latest)，下载 [dsh-multi-chain-0.1.3.tgz](https://github.com/sqx6781268/dsh-smart-route/releases/download/v0.1.3/dsh-multi-chain-0.1.3.tgz)。这是可直接安装的插件包；源码压缩包用于查看、修改和自行打包，不要与安装包混淆。
2. 打开 DSH 的「插件」页面，使用安装入口选择/填写该本地安装包的**完整路径**。这是本地插件包，不需要在本插件中填写任何模型密钥。
3. 等待安装完成，确认插件列表出现「多链路由」并启用。若宿主提示需要重启，先保存正在进行的工作再重启 DSH。
4. 打开「设置 → 内置插件 → 多链路由」。也可以在「插件 → 多链路由详情」进入同一编辑器。
5. 初次安装没有预设的个人渠道，这是正常情况；按下面步骤建立自己的链。

不要为了补依赖而手工安装旧版 `@deepseek-ai/*` 包；插件使用宿主提供的能力。若宿主拒绝版本不兼容，先使用支持的宿主版本，不建议强制豁免后继续。

> **0.1.2 更正说明**：0.1.1 的文字说明曾写有徽标诊断性能优化，但 0.1.1 安装包内的客户端仍是修复前版本（详见 [更新记录](CHANGELOG.md)）。需要这些修复请安装 0.1.2 或更新的 0.1.3；0.1.1 的发行包保持原样不作覆盖。本插件不宣称已修复终端字体卡顿。
>
> **0.1.3 新增图片支持**：链按成员本次实时能力宣称图片，含图请求只交给同时声明「文本 + 图片」的成员；没有这类成员时明确拒绝。详见 [更新记录](CHANGELOG.md)、[配置说明](docs/配置说明.md#图片路由) 与 [图片路由实现说明](docs/图片路由实现说明.md)。

### 从源码使用

下载或克隆源码后，在项目目录执行 `npm test` 检查，再执行 `npm pack` 生成安装包，按上述步骤安装生成的文件。无需构建前端，也不需要下载本地模型。不要把开发者机器上的 profile 配置直接复制到自己的 DSH 中。

## 第一次配置：建立两条可选链

先确认你准备使用的模型，在 DSH 原有模型选择器中单独选择时能正常工作。

### 建立“质量优先”链

1. 打开任一设置入口，点「新增链」。
2. 把名称改为「质量优先」。名称供你识别；ID 填 `quality`，必须与其他链不同。
3. 保持「启用」勾选，策略先用「顺序降级」。
4. 点「添加成员」，从下拉列表选主要模型。
5. 再添加一个备用成员。建议先选用途接近的模型，便于失败后保持任务要求一致。
6. 用「上移」「下移」调整顺序：越靠前越先尝试。确认没有空白成员，再点「保存配置」。
7. 页面显示保存成功后，配置已加载；下一次请求使用新的顺序。

### 再建立“快速响应”链

重复新增，名称用「快速响应」、ID 用 `fast`，把更快的成员放在前面。两条链可以共享成员；同一个成员进入冷却时，两条链都会识别它。

成员下拉来自宿主提供的模型目录。目录超过采样上限时会明确提示截断，未列出不代表该模型不存在；可手动输入真实成员名称。目录里没有的成员可以手动填 `provider/model`，但必须使用真实名称；不是输入一个名称就能创建新的服务渠道。模型 ID 本身有斜杠时可继续填写，只有第一个斜杠用来区分服务渠道与模型。

## 日常怎么用

1. 回到对话，打开模型选择器。
2. 在「多链路由」分组选择「质量优先」或「快速响应」。
3. 正常发送消息或执行任务。
4. 某个成员失败且符合降级规则时，插件自动尝试后续成员；你不需要为这次失败手动重发同一任务。
5. 要改变下一次请求的方案，重新打开模型选择器选另一条链即可。要恢复普通模式，直接选原来的具体模型。

会话顶部的 `⛓ 渠道/模型` 表示**本会话最近实际开始作答的链成员**，不一定等于你刚在输入框选择、但尚未调用的新模型。宿主重启后尚无新请求、当前会话没有记录或查询暂时失败时，徽标会收起。

## 修改、停用与轮转

- **换顺序/换模型**：编辑成员并保存，下一次请求生效。
- **临时停用一条链**：取消「启用」并保存。配置仍在，模型选择器不再提供该链；重新勾选即可恢复。
- **删除成员/链**：确认不再需要后删除，再保存；删除前可自行备份配置文件。
- **顺序降级**：每次从链头开始，适合主力加备用。
- **轮转起点**：在等价成员之间分摊请求；失败时仍会依次尝试其他成员。需要调整连续使用次数时，可用配置文件中的 `stickyLimit`。频繁轮转可能降低提示词缓存命中率。

## 看运行状态与冷却

在编辑器展开「运行状态 · 本次启动」，点「刷新状态」。可以看到每条链最近的尝试、最近降级成员、最近开始作答的成员、最近一次图片筛选结果，以及还在冷却的成员和到期时间。

“已开始作答”不代表这一轮最终成功；如果作答后上游故障，仍可能得到错误。状态只保留本次启动最近一百条路由动作，重启会清空。它用于解释当前情况，不是永久用量账本，也不是所有服务的健康检查。

页面下方可开关冷却并调整分钟数；关闭后新请求立即不再跳过旧冷却成员。自定义冷却错误码和降级错误码请参考 [配置说明](docs/配置说明.md)。

## 两个页面同时打开时

两个入口可以分别浏览和保存，但不要把独立草稿当成实时共享编辑器。一处保存后，另一处的旧草稿会提示冲突并保留，不会直接覆盖已保存内容。

遇到冲突时，先把想保留的改动记下来，再点「重新加载」，基于最新配置重新修改并保存。点重新加载会丢弃当前未保存改动，页面会先提醒你。状态表的「刷新状态」只更新运行记录，不重载编辑中的链。

## 备份、更新与卸载

配置默认保存在当前用户主目录下 `.dsh/multi-chain/chains.json`。Windows 对应 `%USERPROFILE%\.dsh\multi-chain\chains.json`，Linux/macOS 对应 `~/.dsh/multi-chain/chains.json`。如维护者使用了自定义数据目录，以设置页显示的配置路径为准。

更新前备份此文件，再安装新插件包并按宿主提示重启。旧配置省略版本号仍可读取；网页保存时会写入当前版本。配置版本不支持时会明确报错，请勿用旧插件强行覆盖新配置。

卸载时先在插件页停用「多链路由」，再使用宿主的移除入口。配置文件独立保留，重新安装后可以继续使用；是否删除备份与配置由你自己决定。运行中的任务应先结束再停用或卸载。

## 常见问题

**看不到“多链路由”分组？**
先确认插件已安装且启用，至少保存了一条含有效成员且启用的链；安装后宿主要求重启时，需要完成重启。仅安装包依赖而没有启用插件，不代表功能已经加载。

**某成员总是失败？**
先单独选这个模型验证账号、权限和余额，再看状态表的降级码；别把备用链当成修复服务商账号的手段。必要时先停用或移除该成员。

**为什么不在输出一半后换另一个模型续写？**
这样容易混合不同模型的回答或重复执行工具。已经开始回答后的失败会直接告诉你，由你决定是否重试。

**保存失败会丢草稿吗？**
页面会保留当前草稿并显示原因。若是冲突，需重新加载最新配置后再整理；若是格式错误，修正空成员、重复成员或重复 ID 后再保存。

**在哪里配置服务商密钥？**
在 DSH 原有模型/账号设置中配置。本插件只选择已有成员，不提供密钥输入框。报告问题时也不要附上密钥或完整凭据文件。

**可以和其他降级插件一起用吗？**
本插件只在你选中自己的链时生效；其他虚拟链仍可单独选择。为避免复杂循环，首选直接把真实服务渠道加入链，不要把多个虚拟链互相嵌套。

**给链发图片会怎样？**
只有当某成员在本次请求时**同时**声明支持文本与图片，它才会被当作"能看图"的成员。含图片的请求只交给这类成员；链里没有这类成员时，你会直接收到"没有成员同时声明支持文本与图片"的错误，图片不会被转成文字，也不会被交给纯文本成员。想让多轮会话里的历史图片继续可用，请始终使用声明了图片能力的链：一条不宣称图片的链在发请求时，宿主会先把历史图片替换成占位文本，插件拿到时已经看不到原图，也无法恢复。

**怎么知道哪些成员能看图？**
以宿主提供的模型信息为准，插件不提供手工覆盖开关；只声明图像输入（不含文本）的成员不算"能看图"，因为它拿不到整段文本历史。具体的判断规则与已验证范围见 [配置说明](docs/配置说明.md#图片路由)。
